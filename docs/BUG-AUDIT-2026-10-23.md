# HavenOS Launcher — Bug Audit

**Source:** `Screenrecorder-2026-10-23-22-28-55-616.mp4`  
**Recorded:** 23 October 2026  
**Device context:** Tablet, landscape orientation  
**Related product direction:** HavenOS launcher redesign from the shared Claude conversation

## What this audit is for

This is a product-level QA and design audit, not just a list of visual imperfections. A launcher must preserve three promises:

1. Every app and widget remains reachable.
2. The layout remains understandable when the user customizes it.
3. The interface uses the available screen intelligently instead of behaving like a stretched phone screen.

The recording shows that the current build breaks all three promises in several places. The first priority is therefore to repair the layout and interaction model before adding more visual polish.

## Severity scale

- **P0 — Blocker:** launcher is unusable, data/layout may be lost, or a primary action cannot be completed.
- **P1 — Critical:** a core launcher function is unreliable or content becomes inaccessible.
- **P2 — Major:** the experience is visibly broken, confusing, or significantly below the intended quality.
- **P3 — Polish:** inconsistent details that do not block use but reduce trust and perceived quality.

## Executive diagnosis

The central defect is a missing spatial contract. The home screen appears to combine a free-positioned canvas, a grid-based app layout, and independently positioned widgets without one authoritative layout engine. As a result, widgets can sit on top of icons, the selected grid does not describe the actual arrangement, and the dock appears to be treated as part of the page rather than as a persistent system layer.

The redesign must establish one coordinate system, one collision policy, one responsive layout policy, and one source of truth for every surface. Visual improvements should come after those foundations are repaired.

## Likely root causes to verify in code

These are hypotheses, not confirmed implementation facts. Verify them before changing architecture.

1. **Multiple layout authorities.** Home icons, widgets, folders, and dock may each calculate positions independently.
2. **Absolute positioning without occupancy.** Widgets appear to use pixel coordinates without claiming grid cells.
3. **No collision resolver.** Adding or resizing a widget does not push, reject, or preview affected items.
4. **Grid controls are cosmetic.** The selected grid value may update the settings UI without reflowing the actual home layout.
5. **Responsive breakpoints are missing.** The tablet landscape layout looks like a phone layout placed inside a wider viewport.
6. **Dock is page-scoped.** The dock may be rendered inside each page instead of in a persistent shell outside the page pager.
7. **Typography is not measured.** Text containers likely assume one font scale and one line height.
8. **Contrast is wallpaper-blind.** Labels do not calculate contrast locally against the pixels beneath them.
9. **Too much GPU work.** Blur, translucent cards, wallpaper motion, and page transitions may be active at once.
10. **Edit mode lacks a draft state.** Changes may be applied directly without a preview, impact report, or reliable undo.

## Required acceptance tests

### Layout integrity

- No two interactive surfaces may occupy the same cell or hit region.
- A widget resize must either push other items, offer a valid alternative placement, or be rejected with an explanation.
- The dock must remain visible, reachable, and unobstructed on every page and in every orientation.
- A grid setting must produce the exact visible grid it promises.
- Rotating the device must preserve item identity and produce a valid placement, never a collision.

### Customization integrity

- Every edit has an immediate preview before commit when it can move or remove content.
- Every destructive layout change shows an impact summary, for example: “3 apps move to page 2.”
- Undo must restore the complete prior layout, not only the last changed property.
- Resetting a section must never reset unrelated sections.
- The selected item and the scope of every action must be obvious.

### Readability and accessibility

- Labels remain readable on the supplied wallpaper and on a light wallpaper.
- Text survives large font scale without clipping.
- All controls have at least 48dp touch targets.
- Contrast, focus, TalkBack labels, and reduced-motion behavior are tested.
- Icon-only actions expose a tooltip or accessible label.

### Performance

- Page transitions maintain a stable frame rate on the target tablet.
- Blur and parallax have a low-power fallback.
- Reduced-motion mode removes nonessential movement while preserving state changes.
- The home screen remains responsive while widgets update.

## Fix order

### P0/P1 — do before visual refinement

1. Implement one occupancy-aware layout engine.
2. Prevent widget/icon/folder/dock collisions.
3. Make grid settings real and connect them to reflow plus impact preview.
4. Make the dock persistent and page-independent.
5. Fix search/settings clipping and icon contrast.
6. Remove or explicitly reclassify the HNK overlay.
7. Add reliable undo for every layout operation.

### P2 — do before a public beta

1. Replace the fixed landscape panel with a tablet master-detail layout.
2. Create stable Today, Home, Library, and Dock zones.
3. Fix folder and card spacing tokens.
4. Reduce blur/overdraw and repair transitions.
5. Add wallpaper-aware label contrast.
6. Redesign edit mode around selection, preview, and commit.

### P3 — polish after correctness

1. Normalize folder icon padding.
2. Refine card radii, shadows, and separators.
3. Improve empty-state copy and illustrations.
4. Tune motion curves and haptic feedback.

## Definition of done

The launcher is ready for the next design pass only when a user can add, resize, move, duplicate, hide, and remove home items without losing access to another item; when the dock stays stable; when grid settings visibly match the result; and when the same experience feels intentionally designed in both portrait phone and landscape tablet layouts.
