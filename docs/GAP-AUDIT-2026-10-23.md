# GAP AUDIT — HavenOS vs Niagara / Nova / Smart Launcher — 2026-10-23

Exhaustive feature-gap audit ordered by the user ("Don't miss any single feature").
Sources read in full: `~/workspace/fusion-launcher/analysis/niagara-analysis.md`
(Niagara 1.16.31), `nova-analysis.md` (Nova 8.0.18), `smartlauncher-analysis.md`
(Smart Launcher 6.6 build 021). Current tree surveyed by grep; COVERAGE.md claims
were NOT trusted blindly — a feature is "already present" only when a renderer,
store, or UI path in code was found. Pure architecture/infrastructure items from
the analyses (DI frameworks, Room schema shapes, dex-level engine internals,
"no dedicated handling found" non-features) are not user-facing features and are
not counted; they are listed in §5 so the exclusion is auditable.

## Status key (exactly one per feature)

- `already present` — renders/works in the current tree (code location cited).
- `built in this milestone` — built by this worker or a sibling worker in vc5.
  "stored-only" means the setting + Settings UI exist and are honestly labelled,
  but no renderer consumes the value yet; the pending hook is named.
- `removed by user direction` — conflicts with an explicit user removal
  (Minimal-only single design language, no presets/templates, no paged home,
  2026-10-23) or with the builder-prompt v1 rule he set (all features free,
  no ads/accounts/analytics/cloud).
- `blocked` — cannot be built in this milestone: exact technical/platform reason
  + exact coordinator hook (file + function/call site) where one exists.

## Counting rule

Each feature is counted exactly ONCE, in the table of the first analysis that
mentions it (order: Niagara → Nova → Smart). Later tables carry `→` cross-ref
rows naming the feature for per-source completeness; cross-refs are NOT counted.
"Present (in effect)" means HavenOS covers the user-visible role with different
mechanics (e.g. device-admin lock instead of a plugin APK), never a claim that
the reference implementation was copied — all HavenOS code is original;
reference analyses were feature-behavior study only (§2 originality rule).
